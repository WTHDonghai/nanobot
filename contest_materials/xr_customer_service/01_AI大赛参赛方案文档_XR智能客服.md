## 一、项目背景

### 1.1 业务痛点

酒店、景区和文旅企业面临日益增长的客户咨询服务压力：

| 痛点 | 现状 | 影响 |
|------|------|------|
| **咨询量大且重复** | 70%以上的客户咨询集中在产品功能、使用方法、常见问题等重复性问题 | 客服人力被大量重复劳动占据，响应时效下降 |
| **知识分散** | 产品手册、FAQ、历史工单、培训资料分散在多个系统，客服需频繁切换查找 | 查找耗时，回答一致性差，新人上手慢 |
| **知识传承难** | 资深客服的经验留存于个人，离职导致知识断层 | 培训成本高，服务质量波动大 |
| **缺乏智能渠道** | 传统在线客服依赖纯人工，无法提供7×24小时服务 | 非工作时间咨询无人响应，客户体验差 |
| **质量难审计** | 客服回答缺乏溯源，无法系统性地检查准确率 | 错误回答难发现，改进缺乏数据支撑 |

### 1.2 为什么用AI解决

- 大语言模型（LLM）具备语义理解和文本生成能力，能从产品文档中精准检索并生成自然语言回答
- RAG（检索增强生成）技术可以将企业私有知识库与LLM结合，确保回答基于真实产品文档
- 多通道Bot框架可实现一套后台、多端部署，降低接入成本

## 三、解决方案概述

### 3.1 系统定位

西软AI智能客服系统 = **OpenViking知识库底座 + VikingBot多通道Agent + 管理后台**

```
┌─────────────────────────────────────────────────────────────┐
│                      用户触达层                              │
│  ┌─────────┬──────────┬──────────┬────────┬──────────────┐ │
│  │ 飞书     │ 钉钉      │ Web页面   │ 开放API │ 企业微信...   │ │
│  │ (卡片)   │ (动态卡片) │ (西软AI   │ (REST)  │              │ │
│  │          │           │  客服页)  │         │              │ │
│  └─────────┴──────────┴──────────┴────────┴──────────────┘ │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│                      Agent 引擎层                            │
│  ┌──────────┬──────────────┬──────────────┬──────────────┐ │
│  │ 意图路由  │  Agent Loop  │  工具注册     │ 人工接管      │ │
│  │ (智能分类) │ (LLM推理循环) │ (知识检索等)  │ (一键转人工)  │ │
│  └──────────┴──────────────┴──────────────┴──────────────┘ │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│                    知识库底座 (OpenViking)                    │
│  ┌──────────┬──────────────┬──────────────┬──────────────┐ │
│  │ 文档解析  │  向量索引     │  层级检索     │  记忆管理     │
│  │ (PDF/文档)│ (Dense+Sparse)│ (目录定位+语义)│ (会话→长期)  │
│  └──────────┴──────────────┴──────────────┴──────────────┘ │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 核心工作流程

```
1. 客户提问 → 通道接收 → 消息总线
                    ↓
2. 意图路由 → 分类（知识查询/寒暄/能力问询/越狱拦截）
                    ↓
3. Agent Loop → 调用知识检索工具 → OpenViking层级检索
                    ↓
4. 检索结果 → LLM生成回答（附来源引用）
                    ↓
5. 通道渲染 → 返回客户（飞书卡片/钉钉动态卡片/Web等）
                    ↓
6. 会话存档 → 自动提取长期记忆 → 知识库沉淀
```

### 3.3 与现有工作模式的集成

- **客服人员**: 通过Web管理台使用AI辅助回答，或直接让AI接待常见问题
- **知识管理员**: 上传产品文档/FAQ到管理台，系统自动解析和索引
- **管理人员**: 在管理台查看会话统计、检索召回测试、系统健康状态

## 四、详细设计

### 4.1 知识库设计：L0/L1/L2三级上下文

```
L0 (Abstract)    │  一句话摘要           │  用于全局语义搜索，快速定位
L1 (Overview)    │  结构化概述 + 目录     │  用于目录定位和摘要检索
L2 (Content)     │  完整文档原文          │  仅在需要时读取，降低Token消耗
```

- **生成方式**: LLM自动生成L0/L1摘要，底层异步队列处理
- **检索策略**: 先通过L0全局向量检索定位高相关目录 → 递归进入L1子目录 → 按需加载L2原文
- **优势**: 相比传统RAG扁平检索，保留了文档的层级语义结构，检索更精准

### 4.2 意图路由

系统使用LLM驱动的意图分类器，在Agent执行前进行快速预判：

| 意图类别 | 处理方式 | 延迟 |
|----------|----------|------|
| 知识查询 | 进入Agent Loop，执行知识检索 | 正常 |
| 寒暄/问候 | 直接返回预设回复 | < 1s |
| 能力问询 | 返回系统能力说明 | < 1s |
| 越狱/越权 | 安全拦截，返回拒答 | < 1s |
| 人工请求 | 触发人工接管流程 | < 1s |

### 4.3 多通道设计

| 通道 | 特点 | 消息格式 |
|------|------|----------|
| **飞书** | WebSocket长连接，无需公网IP | 交互式卡片，Markdown渲染 |
| **钉钉** | Stream模式 | 动态活体卡片，实时展示AI处理进度（"检索知识库"→"文档读取完成"） |
| **Web页面** | 公共测试页"西软AI客服" | 聊天UI，含历史会话侧栏、PDF导出、人工接管按钮 |
| **开放API** | RESTful接口 | JSON格式，适合第三方系统集成 |

### 4.4 人工接管机制

- AI无法确认答案或识别到敏感/投诉类问题时，自动建议人工接管
- 用户也可主动点击"转人工"按钮
- 接管时将完整会话上下文（含AI已检索到的相关文档）一并传递给人工坐席
- 支持配置接管目标URL或远程服务

### 4.5 安全与治理

| 维度 | 措施 |
|------|------|
| **输入安全** | 意图路由层拦截越狱/越权/内部敏感信息探测 |
| **输出溯源** | 每个AI回答附带来源文档URI，可追溯到原文 |
| **多租户隔离** | account_id + user_id + owner_space三级隔离 |
| **密钥管理** | 模型API Key、bot secret统一通过配置文件管理，不暴露给前端 |
| **人工审核** | 关键回答可由人工确认后发送 |

## 五、技术架构

### 5.1 技术栈

| 层级 | 技术选型 |
|------|----------|
| **后端语言** | Python 3.10+ |
| **Bot框架** | 自研 VikingBot（异步Agent Loop） |
| **知识库** | OpenViking（层级文件系统 + 向量索引） |
| **向量数据库** | RocksDB（嵌入式）/ VikingDB |
| **Embedding模型** | 火山引擎 Doubao Embedding / OpenAI Embedding |
| **LLM** | 火山引擎 Doubao / GPT-4 / Claude 等（可替换） |
| **前端** | React + TypeScript + Vite |
| **部署** | Docker Compose（双容器：OpenViking + VikingBot） |

### 5.2 关键组件

| 组件 | 职责 |
|------|------|
| VikingBot Agent Loop | 核心消息处理循环：意图路由 → 工具调用 → LLM推理 → 回复生成 |
| IntentRouter | LLM驱动的意图分类，秒级响应非知识类请求 |
| OpenViking Server | 文档解析、向量索引、层级检索、记忆管理 |
| Channel Manager | 多通道统一接入和分发 |
| Session Manager | 会话状态管理，上下文保持 |
| Admin Console | Web管理后台：知识管理、会话查看、召回测试、系统监控 |

### 5.3 部署架构

## 八、风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| AI回答不准确 | 客户体验差 | 回答附带来源引用，用户可自行核实；支持人工接管 |
| 知识库覆盖不全 | 部分问题无法回答 | 系统识别知识盲区，提示补充；支持学习模式 |
| LLM服务不稳定 | 系统不可用 | 多模型Provider兜底；关键场景保留人工通道 |
| 数据安全 | 敏感信息泄露 | 意图路由层拦截敏感探测；多租户数据隔离 |
| 用户接受度低 | 使用率不足 | 渐进式引入，AI辅助→AI主导；收集反馈持续优化 |
